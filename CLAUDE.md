# TheCafeSite — Claude instructions

Static site for The Cafe (breakfast, lunch & catering, Leavenworth KS), built with **Eleventy 3 + Nunjucks**. Mirrors the setup of the `mtch.tech` project at `E:\ScriptsGit\mtch.tech` — check there first when a convention is unclear.

## How to report
The owner often works between serving customers and types requests in parts as new issues come up. So:
- **Work quietly, report once.** No step-by-step narration; at the end of a task, a short report: what changed, anything they must do, anything you need from them.
- **Short and scannable.** A few bullets, not paragraphs. Skip what didn't change and how you got there unless asked.
- **A new message mid-task is an addition, not a restart.** Fold it in and keep going.
- Ask only when truly blocked, in one line.

## Planning & tasks
Project planning, decisions, and the task backlog live OUTSIDE this public repo at `E:\GitHub\CafeWork\` (private repo) — read `PLAN.md` there first, take tasks from `TASKS.md`. Never commit business/planning details, pricing strategy, or outreach scripts to this repo.

## Branches
- **`main` is what's live.** A push to `main` deploys the website (GitHub Actions; a push touching only `kitchen/` doesn't), and the kitchen PC pulls `main` when it starts or on Check for updates.
- **`dev` is where work happens.** Commit there, test locally (`npm start` for the site, `kitchen/start-dev.bat` for the board), and merge `dev` into `main` to ship both. Don't commit straight to `main` unless asked.
- **`kitchen-board` is retired** (merged 2026-10-08). It is kept pointing at `main` only so a kitchen PC still on it moves over by itself; don't work on it.
- **Check the branch before every commit** (`git status -sb`): the owner switches branches in his own terminal during a session.

## Build
- `npm start` — Eleventy dev server with live reload on `http://localhost:8080`. Its extensionless URL resolution matches `.htaccess`, so `/catering` works locally exactly as it does in production. **Use this rather than opening files from `file://`**, which cannot resolve extensionless links.
- `npm run build` — clean build into `_site/`, **then exports every `/studio/` piece to PNG (and PDF, where the piece sets `pageSize`) via headless Chrome**. **`_site/` is what gets uploaded**, not `src/`. Both `_site/` and `node_modules/` are gitignored. Chrome or Edge is therefore a build dependency; set `CHROME_PATH` if it is not in a standard location. `npm run export` re-runs just the artwork half.
- Exported pieces are published at `/studio/downloads/` so they can be saved on a phone — see `src/studio/README.md`. `npm start` does not export, so that page is empty until a `npm run build` has run.
- **Studio pieces archive themselves** after 14 days without a change (`src/_lib/studio-archive.js`, dated by git): not built, exported or uploaded, listed under Archive with a GitHub link. `studioPinned: true` keeps one built (the printed menus, the weekly post, the specials signs); `studioWeekly: true` puts it in This week at the top of the downloads page; `studioData` names the data files it's built from. The rule is worked out when a build starts (restart `npm start` after changing it), needs git history (the deploy uses `fetch-depth: 0`), and `STUDIO_ALL=1` builds everything.
- `social/`, `archive/`, `square/`, `kitchen/`, `personal/`, and the `.md` docs stay out of the build entirely. `personal/` holds the owner's non-cafe pieces made with the site's fonts (each folder's README says how to print it); copy one into `src/` only to print it, and never commit it there. **Retired pieces go to `archive/site-src/`** at the path they had under `src/`, never deleted; `archive/README.md` lists them and how to restore one.
- `kitchen/` — the kitchen order board for the mini PC: a dependency-free Node program that polls Square's Orders API and serves a kiosk page on `localhost:8090`. Not part of the site. The Square token lives only in `kitchen/config.json` on that PC (gitignored); `KITCHEN_MOCK=1` runs it on fake orders. For online and DoorDash orders it writes back to Square (`squareStatus`): Done marks them Ready 10 s later (Undo first and Square never hears), Handed off marks them picked up; counter sales are left alone. Each morning it also sets Lunch Special's side lists and the day's words in Lunch Special's and Soup of the Day's descriptions (what online ordering shows) — see `kitchen/README.md`.
- `src/_data/specials.json` — the daily specials, one entry per day in `days` (date, soup, special, sides, and `price` only when a day isn't the usual top-level `price`, which the kitchen PC puts into Square). It holds **this week and next side by side**: next week is added a week ahead while this one is still being served, never by replacing it. Feeds the "Today's special" box at the top of `/menu` (`partials/site/specials-today.njk`, which picks today on Central time in the browser, lists only that one Monday–Sunday week, and **hides anything not today or later** — a stale special must never show); the weekly Facebook post `studio/fb-weekly-specials.njk` (caption generated in its `.11tydata.js`) and the counter sign, which both show the **newest** week (`latestWeek` filter); and `/specials.json` (`src/specials-feed.njk`), which the kitchen PC reads to put each day's plate and soup into Square that morning (`kitchen/README.md`, "Specials" — it never changes today once it's in Square, or a day set on its front page). Weekly routine: add next week's days, `npm run build`, upload, post the PNG + caption from `/studio/downloads/`, then edit last week's Facebook post to start "Outdated. Thank You" (Facebook resurfaces old posts when someone comments); delete a week once it's over, after copying it to `SPECIALS-HISTORY.md` in CafeWork. The printed menus don't list specials; they point to `/menu` and Facebook for them.
- `npm run desserts` — writes `src/_data/desserts.json` (names, prices, sold-out kinds) from Square's desserts as the kitchen board's Manage → Desserts has them, for the dessert fridge sign (`studio/sign-desserts-bw.njk`) and the bars sign. Needs the token in `kitchen/config.json`, so it only works on the owner's PC or the kitchen PC; `npm run build` runs it first and, without a token (the deploy), leaves the committed file alone. Commit `desserts.json` when it changes.
- `npm run square` — rebuilds `square/catalog-import.csv` (the Square catalog import) from `menu.json` via `scripts/square-catalog.py`. **Run it after any menu change** and commit the CSV with it. Square's modifier lists are not generated — `square/README.md` lists them by hand, so a changed pick list (breads, kids sides, BYO) needs that table updated too.
- `npm run thumbs` — makes the `/gallery` grid's small copies (`thumbs/` beside each photo in `src/assets/photos/` and `src/assets/gallery/`) with ImageMagick; run it after adding a photo and commit the thumbnail with it. Without one the gallery shows the full photo, so forgetting it costs page weight, not a broken page.

## Structure
- `src/*.njk` — one file per page. `src/src.11tydata.js` sets `permalink` so pages build to flat files (`catering.njk` → `catering.html`) instead of Eleventy's default `catering/index.html`. This keeps every live URL, canonical tag, and sitemap entry unchanged. Don't remove it without planning redirects.
- `src/_includes/layouts/base.njk` — `<head>`, fonts, canonical/og tags, body shell. `layouts/page.njk` adds nav, `<main>`, and footer; inner pages use it.
- `src/_includes/partials/` — `site/` for the website's pages (`nav.njk`, `footer.njk`, `construction-banner.njk`, `specials-today.njk`, `diet-marks.njk`) and `studio/` for the `/studio/` pieces (menus, signs, filigree, Square placeholders). Nav/footer are **partials, not duplicated per page**, so there is nothing to keep in sync.
- `src/_lib/` — the build's own JavaScript, not templates: `studio-archive.js` (the auto-archive) and `specials-caption.js` (the specials wording, also read by the kitchen board).
- `src/_data/site.json` — name, URL, phone, email, address, the `underConstruction` flag that shows/hides the banner site-wide, and `ordering.url` (the Square Online pickup site). Every "Order Online" button is conditional on that URL, so it stays empty until the Square site exists rather than shipping a dead button. `nav.json` — primary and footer link lists.
- `src/_data/menu.json` — the menu, shared by `/menu`, `/menu-board` and both `/studio/` menu pieces. Sandwiches are three categories: `sandwiches` (cold/deli), `build_sandwich` (build-your-own, priced by meat count via `sizing` + `picks`) and `hot_sandwiches` (the griddle — burgers are part of it since 2026-09-29) — see `_note_hot_cold` and `_note_build_sandwich`. Items name their DEFAULT bread, which is what goes into Square; the swap is a modifier there. A category priced flat carries one `sizing` line instead of a price per row (`_note_flat_price`), and a build-your-own category uses `picks` columns instead of priced rows (`_note_picks`); every template guards `c.items`, so a `picks`-only category is legal. Dietary marks (GF/V) come from its `diets` registry; `dietsConfirmed` gates every mark on the public page — while it is false `/menu` renders no marks, key, filter, or `suitableForDiet`, and the tri-fold carries a proof-only warning instead. Read the `_note_diet` keys before touching a mark.
- `src/reserve.njk` → `/reserve` — table requests (any party size; everyone still orders at the counter). Posts to the cafe's Google Apps Script at `site.reservations.formUrl` (`kitchen/google-script/Code.gs`), which keeps a Google Sheet, emails the cafe and customers, and hands requests to the kitchen PC (Manage → Reservations, `kitchen/README.md`). Empty URL = the page offers the phone number only. The hold time, seating times and days are stated in both `site.json` and `Code.gs`: change both.
- `src/menu-board.njk` → `/menu-board` — the in-store screen, built for a 1920×1080 TV in browser fullscreen. Unlisted: `noindex`, off `nav.json`, off the sitemap — but unlisted is not private, so nothing sensitive goes on it. Scales by a viewport-tied root font-size with **every length in rem**; a `px` value in `menu-board.css` is a bug.
- `src/feedback.njk` → `/feedback` ("Our feedback") — every customer survey summed up, good and bad, from `src/_data/feedbackStats.json` (made by the kitchen PC: Manage → Survey → For the website; replace it whole, never edit it) plus the hand-written themes and "You said, we did" in `feedback.json`. **Not built and not linked while `feedbackStats.total` is 0** (`feedback.11tydata.js`, the footer's `needsFeedback`); add it to `sitemap.xml` once it's live. A customer's words only with the survey's share box ticked, first name and initial at most, no staff names, and **no `AggregateRating` markup** (Google doesn't show stars for a business's own reviews and penalises the markup). `site.reviews.googleUrl` (the Profile's share link, chosen because it opens the cafe's Google page and its review stars, not a sign-in page) adds a Leave a Google review button there and on the survey's thank-you; empty, none shows. `/review` (`src/review.njk`) forwards to it, and the counter sign `sign-review(-bw)` (QR `assets/qr-review.svg`) points there. Every ask says "good or bad" and offers nothing for a review: Google's rules.
- `src/gallery.njk` → `/gallery` — built from data: food from `src/_data/photos.json` (On the menu, Daily specials; newest first) and the catering and cafe photos from `src/_data/gallery.json`. A new photo is one entry there plus `npm run thumbs`; both files' notes say what each field is for. Food and places only, never people: the staff don't want photos of themselves online.
- `src/_includes/partials/site/diet-marks.njk` — the GF/V marks, shared by `/menu` and the board. The macro is ungated on purpose; **the caller applies `menu.dietsConfirmed`**. Read the comment in the partial before using it.
- `src/studio/menu-trifold-bw.njk` and `menu-counter.njk` — the printed menus (client 2026-10-09: the cafe uses the black & white tri-fold and the two-sided 11×17 for ordering), same data, different geometry. Proof both. The tri-fold is `partials/studio/menu-trifold-sheets.njk` with `bw: true` (ink palette, type title); it is also the PDF behind `/menu`'s "Print this menu". It is full: its panels are a fixed 8.5in and **clip rather than reflow**, so adding items means moving a whole category between panels and re-proofing the PNG, not shrinking type. `menu-counter.njk` is the answer when type needs to be bigger: one 11×17 sheet printed both sides (about 14pt descriptions against the tri-fold's 7.5pt, three columns), printed in colour. It is built on `partials/studio/menu-large-print-parts.njk` and `menu-large-print.css` (base sizes from the archived letter-size large print, scaled up by `.lp-stack--counter`; `.lp-stack--bw` is there if a black & white copy is ever wanted). The colour tri-fold, the one-sheet handouts and the 3-page large print are archived (`archive/README.md`). Counter signs for letter stand-up holders: `sign-drinks(-bw)` from menu.json and `sign-specials(-bw)` from specials.json, styled by `sign.css`. Customer survey: `/survey` (`src/survey.njk`, unlisted and noindex, answers by email through Formspree at `site.survey.formUrl`), with its counter sign `sign-survey(-bw)` (QR `assets/qr-survey.svg`) and the paper `survey-card`. Both ask the questions in `src/_data/survey.json`, so they always match. **Proof every menu PNG after any menu change** — an overrun is silent.
- `src/index.njk` — self-contained hero/gateway page. No nav or footer, sets `noSiteJs: true`, carries the JSON-LD via `headExtra`.
- Page-specific CSS lives in `src/assets/css/<page>.css` and is wired up with `pageCss` front matter; shared styles are `style.css` and `tokens.css`. The `/studio/` pieces' stylesheets live in `src/assets/css/studio/` (`piece.css` is their shared base).
- **A tidy-up commit** (moving files, rewriting paths, nothing anyone would see) ends with the trailer `Studio-Dates: unchanged`, so the studio auto-archive doesn't date every piece it touched as new.

## Front matter
`title` and `description` are required. Optional: `ogTitle`, `ogDescription`, `pageCss`, `headExtra`, `bodyClass`, `noSiteJs`, `noindex`.

Write `&` as a literal in front matter, never `&amp;` — Nunjucks escapes these values on output, so a pre-escaped entity ships as `&amp;amp;`.

## Config filters
- `bust` — content-hash query string on asset URLs. Required for CSS/JS because `.htaccess` caches them for 7 days.
- `hasAsset` — true if a file exists in `src/`, for artwork-with-text-fallback patterns.
- `thumb` — a photo's gallery thumbnail (`/assets/photos/x.jpg` → `/assets/photos/thumbs/x.jpg`), or the photo itself when there isn't one yet.
- `inlineSvg` — inlines an SVG's markup so page CSS can color it. An `<img>` is a separate document, so an SVG with no `fill` of its own renders **black** inside one; `assets/thecafe.svg` is outlined with no fill and must be inlined to pick up a color.

## Conventions
- **`STYLE.md` is the style guide**: voice, wording, colour, type, logo, sizes, posts, print and photos in one place. Keep it in step when a rule below or in the code changes.
- Palette: cream `#FAF7F2`, teal `#2C5E70` / `#1F4552`, accent red `#C0392F` / `#A02F26`, mint `#8ED9D4`, `--text-dark #22323A`. Teal and teal-dark are **grounds only** (hero, footer, overlay); red on teal is 1.3:1, never put one on the other. Red accent carries every interactive element. Playfair Display headings, Lato body, via Google Fonts.
- Images lazy-loaded; respect `prefers-reduced-motion`; keep pages accessible (this audience skews older).
- Live site: `https://lvcafetogo.com` (canonical/og:url/sitemap use this host). Internal links are root-absolute and extensionless (`/about`) — `src/.htaccess` rewrites them to the real files.
- `404.html` is served by `ErrorDocument` at whatever path was requested, so it carries `noindex: true` and deliberately has **no canonical or og:url**. Its links are root-absolute so they still work from any depth.
- Social and print artwork is built in `/studio/` (see `src/studio/README.md`). `social/` holds the older fixed-size HTML templates, the LinkedIn kit among them.
